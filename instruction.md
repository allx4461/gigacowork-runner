# GigaCowork Runner v2

Раннер работает с подготовленным локальным кейсом или с кейсом на Яндекс Диске. Он создаёт для каждого прогона отдельный чат GigaCowork, прикрепляет файлы и сохраняет ответы.

## Что нужно до первого запуска

1. Распакуйте всю папку `gigacowork-runner-v2` в любое место, где есть права на запись. Не переносите отдельные файлы из неё.
2. Установите Node.js LTS версии 18 или новее: <https://nodejs.org>.
3. Только для режима Яндекс Диска получите OAuth-токен с правами `cloud_api:disk.read` и `cloud_api:disk.write`. Это секрет: не добавляйте его в файлы кейса и не пересылайте вместе с раннером.
4. Убедитесь, что у вас есть доступ к нужному стенду GigaCowork, пространству и агенту.

При первом запуске раннер сам установит Playwright и Chromium. Появившаяся папка `node_modules` нужна для работы; в передаваемую версию раннера она намеренно не входит.

## Как подготовить тест-кейс на Яндекс Диске

Раннер работает с папкой кейса в стандартной раскладке «Структура кейса» v1.2 (как `Бенчмарк/MGN-001`) и сам находит в ней всё нужное:

```text
MGN-001/
├── Скиллы и промпты/
│   ├── MGN-001_промпт_A.md          ← промпт трека A (ровно один файл на трек)
│   ├── MGN-001_промпт_B.md          ← промпт трека B
│   └── MGN-001_скилл_GigaCowork.md  ← только метка скилла в отчёте
├── Входные данные/                  ← все файлы (с подпапками) прикладываются к сообщению
└── Результаты тестирования/track A|B/GigaCowork/<N> прогон/   ← сюда раннер кладёт артефакты
```

Текст промпта отправляется как есть; перед ним раннер добавляет служебную фразу, что все файлы уже приложены. Имена файлов во «Входных данных» должны различаться (чат не различает подпапки). Если папки «Скиллы и промпты» нет, раннер остановится с ошибкой.

## Запуск всего процесса без терминала

### macOS

1. Дважды щёлкните `Запустить тест.command`. Если macOS блокирует файл, щёлкните по нему правой кнопкой, выберите **Открыть** и подтвердите запуск.
2. При первом запуске установите Node.js, если скрипт попросит об этом.
3. Если входа на стенд ещё нет, в браузере войдите в GigaCowork и вернитесь в окно терминала.
4. Выберите `1` для локального кейса или `2` для Яндекс Диска. В режиме Диска потребуется токен; символы при вводе не отображаются.
5. Локально выберите в диалоге готовую папку трека с `plugin.yaml` и `evals/` (например, `MFG-002/Автотесты/track-A`), затем укажите трек, ссылку на пространство и число прогонов. Для B можно ввести имя существующего агента или оставить пустым. Навык заранее добавляется в пространство и не проверяется раннером.
6. Для Диска выберите трек, папку теста на Диске и пространство. Не закрывайте окно до завершения. Откроется папка локальных результатов или отчёта на Диске.

Локальный режим использует `evals/кейс-…/prompt.md` и файлы из папок `Данные агента…`; эталон держите вне них. Результаты сохраняются в `evals/results/<идентификатор>/` выбранного трека: `факты.md`, `run-log.json`, ответы, ленты и скачанные файлы. Сводный отчёт и оценка по эталону автоматически не формируются.

В обоих режимах окно с вопросами открывается в терминале, но вводить команды не нужно. Браузер теста скрыт; завершение запуска не гарантирует, что каждый прогон успешен — проверяйте статусы.

### Windows

Запустите `Запустить тест.bat` двойным щелчком и выполните те же шаги. В Windows токен при вводе отображается в консоли, поэтому не запускайте файл при посторонних.

Если сессия стенда истекла, отдельно запустите `Войти на стенд.command` на macOS или `Войти на стенд.bat` на Windows, войдите в браузере и затем повторите тест.

## Выбор трека и агента

В режиме Яндекс Диска раннер предлагает два режима:

- **A** — обычный чат без выбранного агента;
- **B** — чат с агентом. Раннер открывает меню **«Добавить агента»** и выбирает агента по точному имени.

Для трека **B** заранее проверьте в GigaCowork, что агент добавлен в выбранное пространство и к нему привязан нужный навык. Поле с названием и версией навыка в раннере — метка для отчёта: раннер не создаёт привязку и не проверяет её автоматически.

Если кейсу нужен скилл, но не нужен агент (скилл доступен в пространстве), запускайте трек B с `--no-agent` или оставьте имя агента пустым в вопросе раннера: чат откроется без агента, скилл попадёт в отчёт как метка. Скилл при этом тоже должен быть подключён заранее.

Важно: «тегирование агента» в v2 — это выбор агента в новом чате, а не текстовая конструкция вида `@Имя` в промпте. Не добавляйте `@Имя` в `промпт.md`, если этого не требует сам кейс.

## Запуск из терминала

Откройте терминал в папке раннера и один раз выполните:

```bash
npm run setup
node cowork.mjs login --stand https://demo.cowork.ru
```

Во время `login` войдите на стенд в открывшемся браузере, затем нажмите Enter в терминале. Сессия сохраняется локально в `~/.skill-craft/storage-state.json`.

Токен Диска можно записать одной строкой в `~/.skill-craft/yadisk-token` или передать через переменную окружения `YADISK_TOKEN`.

Интерактивный запуск:

```bash
node yadisk-test.mjs
```

Запуск без вопросов, без агента:

```bash
node yadisk-test.mjs \
  --track A \
  --disk-folder "Бенчмарк/MGN-001" \
  --workspace "MFG тесты" \
  --runs 3 \
  --timeout-min 45
```

Запуск с агентом и меткой навыка:

```bash
node yadisk-test.mjs \
  --track B \
  --agent "Юрист по договорам" \
  --skill "Проверка договоров, v2" \
  --disk-folder "Бенчмарк/MGN-001" \
  --workspace "MFG тесты" \
  --runs 3 \
  --timeout-min 45
```

`--workspace` принимает точное название пространства или его URL. Основные параметры:

| Параметр | Назначение |
|---|---|
| `--disk-folder` | путь к папке кейса на Яндекс Диске |
| `--workspace` | название либо URL пространства |
| `--track A` / `--track B` | запуск без агента / с агентом |
| `--agent` | точное имя агента для трека B |
| `--skill` | название и версия навыка для отчёта |
| `--runs` | число независимых прогонов; по умолчанию `3` |
| `--timeout-min` | максимум ожидания ответа в одном прогоне; по умолчанию `45` |
| `--stand` | адрес стенда; по умолчанию `https://demo.cowork.ru` |
| `--report-folder` | базовая папка лент и времени (по умолчанию `<кейс>/Отчёты/Запуски раннера`) |
| `--dry-run` | скачивает и собирает кейс локально, но не открывает стенд |

## Результаты

На Яндекс Диск выкладываются только артефакты, лента и время замера:

- `<кейс>/Результаты тестирования/track X/GigaCowork/<N> прогон/` — файлы, созданные агентом (входные файлы отфильтрованы), только для **завершённых** прогонов. Номер — первый свободный: папки, где уже лежат файлы, не трогаются; пустые заготовки используются. Соответствие локального прогона и номера — в `время.json` (`diskRun`).
- `<кейс>/Отчёты/Запуски раннера/<дата-ID>/ленты/прогон-<r>.md` — лента чата.
- `<кейс>/Отчёты/Запуски раннера/<дата-ID>/время.json` — время замера, статусы, ссылка на чат, аномалии.
- `<кейс>/Отчёты/Запуски раннера/<дата-ID>/неполные-прогоны/` — артефакты прогонов со статусом `incomplete`/`error`: в «Результаты тестирования» они намеренно не попадают, чтобы оценщик не принял их за завершённые.

Ленты и время лежат отдельно от артефактов, потому что оценщики кейсов выбирают файлы из папки прогона по расширению (в FESKO-001 артефакты бывают `.md`).

Локальная копия со всеми деталями (`ответ.md`, `факты.md`, скриншоты ошибок) остаётся в `runs/` рядом с раннером. Каждый прогон всегда открывает новый чат. Статус `incomplete` означает, что агент задал вопрос, а в тест-кейсе нет подготовленного ответа: такой прогон не считается завершённым.

В `run-log.json` поле `answerSec` — сумма времени ответов от отправки до обнаружения их завершения; `responseTimesSec` содержит время каждого ответа по отдельности. Подготовка чата, вложений и ответы на уточнения в этот замер не входят. Окончание определяется по кнопке остановки и стабильности ленты, поэтому замер включает время ожидания стабильности (по умолчанию 6 секунд) и задержку опроса. `setupToAnswerSec` включает подготовку до последнего ответа, `totalSec` — весь прогон, включая скачивание. Новые журналы помечены `timingVersion: 2`; в старых `answerSec` включало подготовку и напрямую несопоставимо с новым.

## Дополнительные возможности v2

### Развёртывание плагина

Если есть папка плагина с `plugin.yaml`, `agents/*.md`, а при необходимости `skills/` и `commands/`, раннер может создать пространство, агента, загрузить навыки, создать команды и привязать их:

```bash
node cowork.mjs deploy "/путь/к/плагину" --stand https://demo.cowork.ru
```

Состояние развёртывания сохраняется в `~/.skill-craft/stand/`, поэтому повторный запуск продолжает незавершённые шаги. Для нового развёртывания используйте `--fresh`.

### Одноразовый чат с выбранным агентом

Создать чат, выбрать агента, приложить файлы и отправить запрос:

```bash
node cowork.mjs chat send \
  --url "https://demo.cowork.ru/workspaces/<UUID>" \
  --agent "Юрист по договорам" \
  --text "Проверь приложенный договор и перечисли риски." \
  --attach "./договор.pdf" \
  --out "./ответ.md"
```

Агент должен быть добавлен в указанное пространство; иначе раннер явно сообщит, что не нашёл его в меню **«Добавить агента»**.

### Команды агента

Запустить команду, привязанную к агенту или пространству:

```bash
node cowork.mjs chat command "проверить-договор" \
  --url "https://demo.cowork.ru/workspaces/<UUID>" \
  --agent "Юрист по договорам" \
  --args "договор.pdf"
```

### Калибровка после изменения интерфейса стенда

Если раннер перестал находить кнопку или поле, откройте инспектор:

```bash
node cowork.mjs inspect --stand https://demo.cowork.ru
```

Новые селекторы сохраните в `~/.skill-craft/selectors.local.json`: этот файл переопределяет `selectors.json` локально и не требует менять переданную папку раннера.
